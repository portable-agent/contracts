# Контракт Conversation Service

`POST /api/v1/messages` — внутренний вход для сообщения после проверки канала. Conversation Service
владеет состоянием диалога и одинаково работает для Web, Telegram, VK и будущих адаптеров.

## Запрос

Первое сообщение не содержит `conversationId`. Сервис создаёт его и возвращает в ответе. Следующие
сообщения передают этот ID, поэтому уточнение попадает в нужный диалог. Остальные поля совпадают с
общим входом Channel Gateway. Identity не передаётся полями JSON: `tenantId` и пользователь берутся
из проверенного Bearer JWT. Пара
`tenantId + subject + requestKey` является ключом повтора.

## Ответ

Ответ содержит `messageId`, `conversationId` и один из двух вариантов:

- `text` — безопасный текстовый вопрос, если данных недостаточно;
- `confirmation` — карточка уже сохранённого действия с `actionId` и `payloadHash`.

Карточка использует `schemas/action-confirmation.schema.json`. Она не является командой выполнения.
Решение пользователя отправляется в Action API вместе с тем же `payloadHash`, поэтому изменённую или
устаревшую карточку нельзя подтвердить молча.

## Граница ответственности

Conversation Service вызывает Agent Runtime, а при полном предложении создаёт действие через Action
Service. Канал не повторяет эту цепочку. Widget SDK только проверяет и отображает карточку.

Точные правила вопросов и тексты карточки пока не определены контрактом: это следующая продуктовая
задача.
